# RoachNet v1.0.5 Performance and Polish Pass

## Scope

This pass targets two user-visible release surfaces without changing product behavior:

1. native runtime-status refreshes in the local Node API;
2. decorative SwiftUI motion in the macOS design system.

The existing dirty worktree and unrelated prior-agent changes were preserved.

## Runtime status responsiveness

### Finding

Each `roachClawStatus()` refresh repeated the same loopback work:

- Ollama reachability was checked by `ensureOllama()`;
- the same reachability endpoint was checked again by `providerStatus()`;
- `installedModels()` called `ensureOllama()` again before loading `/api/tags`.

Concurrent refreshes also duplicated one another. Eight simultaneous status requests could therefore issue 24 identical `/api/version` probes and eight identical `/api/tags` requests.

### Improvement

`scripts/lib/roachnet_async_cache.mjs` now provides a small dependency-free async TTL cache that:

- coalesces in-flight requests by key;
- caches resolved values for a bounded interval;
- never caches rejected loads;
- supports explicit invalidation.

The native API uses a one-second default cache for runtime reachability and installed-model snapshots. The interval can be tuned with `ROACHNET_RUNTIME_PROBE_CACHE_MS`. Cache entries are invalidated when RoachNet starts Ollama and before/after a model pull, including failed or transport-ambiguous pulls, so lifecycle changes are not hidden.

### Evidence

The integration test sends eight simultaneous `/api/roachclaw/status` requests to a real child native-API process backed by an instrumented fake Ollama server. All eight responses report the provider and installed model correctly while the fake server records exactly:

- one `/api/version` request;
- one `/api/tags` request.

This proves both request coalescing and response preservation at the HTTP boundary.

The same integration test forces a model pull to change the model catalog and then return an error. It repopulates the old catalog while the pull is in flight and verifies that completion invalidates that stale snapshot on the failure path.

## macOS motion accessibility

### Finding

`RoachBackground` already honored the macOS Reduce Motion setting, but six other timeline-driven decorative surfaces did not:

- animated panel chrome;
- spotlight-panel dither;
- the RoachNet orbit mark;
- the Home mascot;
- launch-reel scanlines;
- the About signal meter.

Those timelines continued redrawing their canvases at 16–18 frames per second even when the user explicitly requested reduced motion.

### Improvement

All seven app timelines now read `accessibilityReduceMotion`, render a stable frame, and pause their schedule when the setting is enabled. The About window's separate heart, backdrop, and status-loop animations also stop immediately when Reduce Motion is enabled and restart if it is disabled while the window remains open. This removes unnecessary redraw work and applies the same accessibility contract across the release app.

### Evidence

A release regression test recursively audits every Swift file under `native/macos/Sources` and fails if any `TimelineView` lacks a `paused: reduceMotion` schedule. It currently accounts for all seven intentional timelines rather than permitting an unbound exception.

## Verification

Run from the repository root:

```bash
node --test scripts/tests/roachnet-performance.test.mjs
npm test
npm audit --audit-level=high
npm run convex:typecheck
git diff --check
```

Native Swift compilation still requires the macOS/Xcode release lane. This Linux worker can validate the release audit around the Swift source but cannot execute `xcrun swift test` or inspect runtime rendering on macOS.
