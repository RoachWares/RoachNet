# RoachNet 1.0.6 and RoachNet-iOS 0.2.0 — pre-publication security review

Reviewed: 2026-10-10, on the release candidates `release/v1.0.6-polish` (RoachNet) and `feature/ios-0.2.0` (RoachNet-iOS), by reading the Swift runtime, app, installer, companion and workflow sources end to end, running the repository's own audits, and probing the built runtime with the contract tests. Findings are listed with what was done about them. "Fixed in 19a57e0" refers to the RoachNet commit; iOS fixes are in the 0.2.0 (6) build.

## Scope

- Dependencies and supply chain (npm lockfile, downloaded build inputs, SBOM and vulnerability evidence)
- Authentication and authorization (loopback API, RoachTail companion bridge, Org routes)
- Local storage, Vault and credential handling
- Network communication, update mechanism, release integrity
- Process and filesystem boundaries, the privileged hosts-file alias
- macOS signing and Gatekeeper; iOS entitlements and App Store compliance
- GitHub Actions permissions and workflow security
- Privacy and telemetry

## Findings and remediation

| # | Severity | Component | Finding | Status |
| --- | --- | --- | --- | --- |
| M1 | High | Mac runtime, update lane | The installer URL from the GitHub Releases API was downloaded with no checksum or signature check (`http://` accepted) and then opened. Anyone who could alter the API response could get a DMG mounted. | **Fixed in 19a57e0.** The `.sha256` sidecar is required and fetched first; the download is verified against it, a mismatch deletes the file, assets must be https. Covered by three new contract tests. |
| M2 | Medium | Mac runtime, HTTP server | `Content-Length: -1` trapped the process on a range bound; a huge chunked size overflowed `data.count + size`. The companion pair route reads the body before auth, so a reachable attacker could kill the runtime. | **Fixed in 19a57e0.** Negative or non-numeric lengths are a 400; chunk sizes are bounds-checked before arithmetic. Covered by a raw-socket contract test. |
| M3 | Medium | Mac runtime, loopback API | No Host check (DNS rebinding could read responses) and JSON bodies were parsed regardless of Content-Type (simple-request CSRF from any browser tab). | **Fixed in 19a57e0.** Loopback Host required; JSON bodies must be `application/json`. The in-process companion proxy is unaffected. A per-launch bearer token for the loopback API is scheduled for 1.1 (ROA-39). |
| M4 | Medium | Mac runtime, companion installs | A paired phone could make the Mac fetch any http(s) URL (blind SSRF, unbounded descriptor bodies). | **Fixed in 19a57e0.** Peer-originated installs must target public hosts; descriptors capped at 2 MB. Owner-originated installs keep LAN mirrors. |
| M5 | Medium | Mac runtime, RoachTail | A join code stayed valid after a successful pairing, there was no attempt limit, and a pairing device could choose its own peer id (overwriting another peer's token hash). | **Fixed in 19a57e0.** One pairing per code, five wrong guesses retire it, ids are server-generated, constant-time compare. Covered by a contract test. |
| M6 | Medium | Installer | Setup strips quarantine from the installed app and ad-hoc re-signs it if `codesign --verify` fails. | **Accepted for 1.0.6, documented.** This is what makes an unsigned, non-notarized release installable at all. Once Developer ID signing exists (1.1 release train), a verification failure must abort. |
| M7 | Low | Mac runtime | Installer config (companion token), RoachTail state and provider key files were created 0644. | **Fixed in 19a57e0.** Written 0600. |
| M8 | Low | Mac runtime | The companion token was inherited by the Ollama child process. | **Fixed in 19a57e0.** Stripped from the child environment. |
| M9 | Low | Installer | The privileged `/etc/hosts` rewrite accepted any `ROACHNET_LOCAL_HOSTNAME` text. | **Fixed in 19a57e0.** Only a plain hostname is accepted; otherwise the default. |
| M10 | Low | Setup service | The setup loopback service accepted non-loopback Host and non-JSON bodies. | **Fixed in 19a57e0.** Same checks as the runtime API. |
| M11 | Info | Mac runtime | Peer tokens never expire; `/api/roachclaw/tokens` mints tokens nothing validates; webhook secrets are unsalted SHA-256. No Vault encryption is claimed or present (plain files under the storage root). | **Open, recorded for 1.1** (ROA-39). |
| S1 | High | Release evidence | The OSV "vulnerability scan" queried `pkg:github/...` purls, which OSV does not index, so it passed for every version. | **Fixed in 19a57e0.** Ollama is queried as a Go module. Nine open Go advisories exist for Ollama 0.40.2 with no fixed version; each is reviewed and accepted in `runtime-freshness.json` with the loopback-only reasoning (see below). |
| S2 | Medium | Release evidence | The SBOM listed a Node.js runtime although the default artifact ships none. | **Fixed in 19a57e0.** Node is emitted as `not-bundled` unless the compat bundle is built. |
| S3 | Medium | Build inputs | RoachSpeech Core ML packs are pulled from third-party Hugging Face mirrors pinned by commit but without per-file digests. | **Open, recorded for 1.1** (ROA-40). The packs are not part of the 1.0.6 DMG's required install path; the baseline pack is bundled from the same pinned commits that the 1.0.5 release used. |
| S4 | Medium | Workflows | Docker-image workflows authorized actors by substring (`contains`) and used mutable action tags; Apple secrets are job-level env in the stage job. | **Partly fixed in 19a57e0.** Exact-match actor check and SHA-pinned actions everywhere. Secret scoping in the (currently unused) stage job is recorded for the 1.1 release train. |
| S5 | Info | Build inputs | Non-pinned diagnostic builds download the latest Ollama unverified; the Node compat cache is reused unverified. | **Open, recorded** (ROA-40). Neither path is used for the release artifact. |
| I1 | High | iOS | A `roachnet://pair` link could repoint the app at any https host while keeping the stored peer token, which the app then sent as a bearer on its next refresh. Any app on the phone can open the scheme. | **Fixed in 0.2.0 (6).** A link that changes the Mac or carries a token is shown in a confirmation alert naming the host; changing the Mac clears the stored token. Covered by a UI test. |
| I2 | High | iOS | Plaintext `http://` to `RoachNet`, `*.local` and private addresses with no server identity check; a host answering for the name on shared Wi-Fi receives the token. | **Accepted for 0.2.0, documented.** This is the 1.0.x RoachTail design (same as 0.1.5); the mitigation is that peer tokens are per-device, hashed at rest and revocable from the Mac. Pinned TLS delivered at pairing time is scheduled for 1.1 (ROA-41). |
| I3 | Medium | iOS | `roachnet://install-content` forwarded attacker-chosen install intents to the Mac without confirmation. | **Fixed in 0.2.0 (6).** Confirmation alert before anything is sent. |
| I4 | Medium | iOS | The RoachPhone GPS BLE characteristic was readable by any nearby central. | **Fixed in 0.2.0 (6).** Read and notify now require an encrypted (bonded) link. |
| I5 | Medium | iOS | No `PrivacyInfo.xcprivacy`; `ITSAppUsesNonExemptEncryption` missing. | **Fixed in 0.2.0 (6).** Manifest declares the UserDefaults reason and no tracking; encryption exemption set. |
| I6 | Low | iOS | The defaults cache (backed up) held the Mac's live join code and pairing payload. | **Fixed in 0.2.0 (6).** Stripped before caching. |
| I7 | Low | iOS | Server-supplied shelf routes were opened as absolute URLs of any scheme. | **Fixed in 0.2.0 (6).** Routes must be paths on the paired Mac. |
| I8 | Low | iOS | Org decisions rely on the stored token only; no local re-auth. | **Open, recorded for 1.1** (ROA-41). |

## Checked and found sound

Loopback bind enforcement for both listeners; constant-time primary-token compare; peer tokens stored only as SHA-256 and never echoed; join code hidden from peers; proxy does not forward client headers; request and response size caps; JSON depth and header limits; download filename sanitisation and partial-file cleanup; provider base URLs block private ranges; exports and diagnostics redact hashes, tokens and signatures; every `Process` launch uses argv arrays; no telemetry, analytics or crash reporting — the only launch-time network activity is a `github.com` DNS lookup for the internet indicator and loopback Ollama probes; update checks are manual. iOS: token in Keychain (`AfterFirstUnlockThisDeviceOnly`), no `NSAllowsArbitraryLoads`, no background modes, on-device speech recognition enforced, no private API or dynamic code. Workflows: top-level `contents: read`, `persist-credentials: false`, inputs passed through `env`, no `pull_request_target`, SHA-pinned actions, quarantine-then-promote release design.

## Signing and notarization

RoachNet 1.0.6 is ad-hoc signed and **not Apple-notarized**, as v1.0.5 was. Gatekeeper blocks the first launch of RoachNet Setup until the person chooses Open Anyway. The repository's `native-packages.yml`/`release.yml` stage-and-promote pipeline requires Developer ID and notary credentials that are not configured on the repository (no secrets or environments exist), so it could not be used; the release is published directly from the gated artifact, the way v1.0.5 was. Obtaining a Developer ID certificate is the top release-engineering item for 1.1.

## Accepted Ollama advisories (bundled 0.40.2)

OSV lists GO-2025-3557, 3558, 3559, 3582, 3689, 3695, 3824, 4251 and GO-2026-5750 against every published Ollama version. They are crafted-model and crafted-request denial-of-service, a registry token exposure, missing authentication on model management and a manifest path traversal. In RoachNet the Ollama server binds to `127.0.0.1:36434`, is reachable only by processes on the same Mac, and loads only models the person chose, so the exposure is that of any local port. 1.1 retires the bundled Ollama in favour of the native RoachInference engine (ROA-30). The accepted list, with reasons, lives in `docs/release-gates/runtime-freshness.json` and is what the vulnerability gate checks against.

## Dependencies

`npm audit --package-lock-only`: 0 vulnerabilities (all 31 locked packages are dev-only and none ship in the artifact). Dead `overrides` for packages no longer in the tree remain in `package.json` and are cleaned up in 1.1.
