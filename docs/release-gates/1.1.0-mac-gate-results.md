# 1.1.0 Mac gate results

- **Machine:** "probook", an Apple M2 Pro (12 cores, 16 GB) running macOS 26.6.1 (25G76) with Xcode 27.0 (27A266a) and Swift 6.4.
- **Date:** 2026-10-12
- **Branch:** `release/v1.1` (`feature/1.1-feature-packs` plus the 1.0.7 release, merged with the 1.1 tree kept)
- **Built from:** `26f259d`. This file and a fix to the simulator check script (`scripts/ios-simulator-pairing`, not part of the app) are committed after the build, so the tag is later than the build commit and changes nothing that ships.

The gate follows `1.0.6-mac-gate-checklist.md`, plus checks for what 1.1 adds: RoachInference and its model server, RoachNet Cluster, RoachTrace, bring-your-own agents and plan models, the Org boards, themes and theme packs, feature packs, the Maps viewer, the local API token and the build stamp.

1.1 was first gated on 2026-10-11 at `46f97b1`, then held for the expanded scope in `docs/1.1/EXPANDED-SCOPE.md`. That candidate (`90a286c1…4c09`) was not published. Everything below is from the expanded build unless a row says otherwise.

## Fixes made during the gate

| Change | Why |
| --- | --- |
| The release-scope audit allows the system `dnssd` module (`26f259d`). | RoachNet Cluster's Bonjour discovery imports Apple's DNS Service Discovery library (part of libSystem). The audit of the first expanded dist refused the import. |
| The simulator check enrolls Face ID on its throwaway simulator and answers the unlock prompt with a matching face; text fields are tapped until they have keyboard focus. | RoachNet iOS 0.3.0 asks for Face ID or the passcode before an Org decision. On the iOS 26.5 simulator the passcode sheet appeared, the approval correctly stayed pending, and the check's approval phase failed. One run also failed when a tap landed before the join sheet took focus. |
| RoachClaw status, warnings and the service catalog name the RoachInference model server instead of Ollama when the native engine serves the models (`415775c`). | 1.1 still said "Powered by Ollama" and "Ollama is not reachable" with no Ollama anywhere. |
| `/api/companion/install` accepts the store's `pack` action and installs that pack by id from the runtime's own pack catalog (`707e889`). Contract test for the missing-id and unknown-pack answers; `smoke:ios-companion-compat` checks every pack item against `collections/packs.json`. | apps.roachnet.org lists theme and speech packs as `pack` items. The Mac app took them from an install link, but a paired phone got 400 "Unsupported App Store install action" and queued the install forever. |
| RoachNet iOS 0.3.0 stops queueing an install the Mac refused (a 4xx other than 408/429) and says why. Against a 1.0.x Mac, a pack item says it needs RoachNet 1.1 or later. | The same bug from the phone's side: a refused item sat at the head of the queue and blocked the rest. |
| `RoachInferenceTests` excludes its `Fixtures` folder from the target's resources (`415775c`). | The release build of all targets had one SwiftPM warning about unhandled files. |
| The iOS marketing UI test scrolls the Org card above the floating tab bar before tapping it. | The tap landed on the tab bar on the iPhone 17 Pro simulator. |
| `NativeModelStore.pull` uses the download lane's 90-second stall timeout and six attempts, and resumes with `Range` after a stall or a transient error (`46f97b1`). Three new tests. | Each transfer ran on one 6-hour clock for stall and total, so a connection that stopped sending held the pull for up to six hours. |

## Notes

- Bundled Ollama is retired in 1.1, so the nine open Ollama advisories accepted for 1.0.7 no longer apply to this build. `ROACHNET_INFERENCE_ENGINE=ollama` uses an Ollama the person installed themselves.
- Signing is ad-hoc, like 1.0.6 and 1.0.7. Developer ID signing and notarization need credentials the release Mac does not have.
- The speech packs in the store are the archives already hosted for 1.0.5 and later; their recorded digests are unchanged. The archives this build wrote are byte-different zips of the same files and were not uploaded.
