## Artifact-bound release-body rule

`docs/releases/1.0.6.md` is honest RC copy and deliberately states that no final artifact identity exists. It must not be promoted unchanged as the stable GitHub body.

The current workflows require a tracked notes file before the artifact is built, but stable policy also requires that the release body contain the artifact's final URL, byte size, and SHA-256. Those values cannot be committed into the same candidate that produces them without changing the candidate and rebuilding it. The release implementation must therefore render immutable stable copy from the tracked RC source plus the staged provenance values, record the rendered body digest, and verify that body before `GO-LIVE`. Editing the tracked source candidate after the build or moving the tag is not an acceptable substitute.

Required rendered artifact block:

```text
Artifact:
- Download: {FINAL_DMG_URL}
- Size: {FINAL_DMG_BYTES} bytes
- SHA-256: {FINAL_DMG_SHA256}
- Checksum sidecar: {FINAL_SHA256_URL}
- Developer ID: {FINAL_DEVELOPER_ID_LABEL} (Team {FINAL_TEAM_ID})
- Notarization: Accepted; stapled; Gatekeeper verified
```

The stable body may use that final line only when all three results are candidate-specific `PASS`.
