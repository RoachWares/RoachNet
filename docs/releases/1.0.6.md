# RoachNet 1.0.6 release candidate

Release date: not scheduled
Version/build: 1.0.6 / 106
Source candidate: pending final selection; the selected full commit SHA must be bound to immutable `v1.0.6` before artifact staging
Platform: Apple Silicon Mac, macOS 14 or later
Installer: `RoachNet-Setup-macOS.dmg`
Status: draft — RC/pre-release only

RoachNet 1.0.6 is a source candidate, not a stable release. The Apple Silicon build, Developer ID signature, hardened runtime, notarization, stapling, Gatekeeper assessment, install/upgrade tests, accessibility review, performance soak, and exact staged/public-byte checks have not run for this candidate. Keep v1.0.5 on the stable channel until the candidate record reports `GO`.

## What changed

- **No more bundled Node.** The local runtime is now `roachnet-runtime`, a native Swift helper inside `RoachNet.app/Contents/Helpers/` that uses only Apple system frameworks. It replaces the embedded Node 26 runtime and the bundled `RoachNetSource` tree, serves the same loopback API, and runs the iOS companion bridge in-process. The default build refuses to package Node; `ROACHNET_BUNDLE_NODE_COMPAT=1` exists only for legacy compatibility builds.
- **Native installer.** RoachNet Setup now drives the same helper (`roachnet-runtime --setup`). It checks for Apple Silicon (including Rosetta-translated launches), macOS 14 or later, free disk space and a writable, non-installer-media location, then stages the install beside the target, installs the contained Ollama runner, boots the staged runtime as a smoke test, and only then swaps it in. User storage is carried across upgrades, and a failed install rolls back and leaves no staging folders behind. The RoachClaw starter model is chosen by installed memory.
- **Headless and Homebrew installs.** `roachnet-runtime --install` runs that staged install without the UI, so the Homebrew cask no longer unpacks a Node source tree or writes `.env` files.
- **RoachTail local alias in Swift.** The `RoachNet` hostname alias is written natively, with a one-time administrator prompt only when `/etc/hosts` needs it.
- **Bundled Ollama 0.40.1.** The reviewed pin moves from 0.33.1 to 0.40.1. The checksum matches the GitHub release digest and the archive layout is unchanged.
- RoachClaw now exposes more of its local operating state in the native app: playbooks, service health, scoped tools, jobs, reports, memory, backups, provider routes, and agent-run summaries. The source and Node behavior tests are present; final macOS interaction and visual behavior still require candidate-specific testing.
- RoachTail now has a native local control-plane state with expiring join codes, peer-scoped tokens, approved routes, and relay metadata. Peer tokens are returned once and stored as SHA-256 hashes rather than plaintext tokens.
- Repeated RoachClaw status refreshes share short-lived Ollama reachability and model-list probes. Tests cover concurrent refreshes and stale-cache invalidation after an ambiguous or failed model pull.
- Decorative timelines in the macOS shell now stop when Reduce Motion is enabled, including changes made while a view is already open.
- The launch guide no longer carries a stale v1.0.5 label, and the native brand mark has a non-insect fallback when the packaged icon is unavailable.
- The public source candidate removes the vulnerable legacy `admin/` WebUI. Its last tracked state remains available from tag `v1.0.5`; it is not part of the 1.0.6 desktop runtime or installer.
- Release automation now stages a signed RC as a quarantined draft and requires exact-byte verification before promotion. It no longer reuses v1.0.5 or replaces release assets in place.

## Security and privacy

- The native API remains bound to loopback. The companion server now rejects any configured non-loopback bind host before it opens a listener; RoachTail join codes and peer tokens are sensitive, and stored peer records keep token hashes, not reusable plaintext tokens.
- The iOS compatibility smoke now turns a missing child executable (for example, `ruby` on a minimal source host) into a controlled actionable failure rather than an unhandled Node child-process error.
- Intake limits now cover JSON requests, chat and mail attachments, Vault and gallery imports, speech audio, calendar imports, and downloads. Final mounted-artifact security and privacy review is still required.
- Root dependency audit and the source test suite pass beyond three explicit macOS-only skips. The public-release-surface audit preserves required imported-source attribution in `docs/UPSTREAM.md` while continuing to reject stale upstream identity in unauthorized public copy. These source results do not establish the state of the final macOS bundle, which still needs its own SBOM, binary/license inventory, and candidate-bound vulnerability scan.
- Optional OpenAI, Anthropic, OpenRouter, external memory, webhook, and other remote provider routes remain user-configured. Do not configure cloud credentials in this RC until the Apple-host privacy review has passed.

## Install, upgrade, backup, rollback, and removal

These are the intended procedures. They are not certified for 1.0.6 until the Apple-host candidate record marks the corresponding gates `PASS`.

### Fresh install

1. Keep v1.0.5 installed unless you are deliberately testing the RC.
2. Verify the downloaded DMG against its attached `.sha256` sidecar before opening it.
3. Open `RoachNet Setup.app` from the DMG. The default contained root is `~/RoachNet`, with the app at `~/RoachNet/app/RoachNet.app` and user data under `~/RoachNet/storage`.
4. A custom contained root may be selected during setup. Record it before testing backup, rollback, or removal.

The required free-disk budget and install duration have not been measured for this candidate. Treat that missing evidence as a stable-release blocker.

### Upgrade and backup

Before an overwrite upgrade, quit RoachNet and copy the entire chosen `storage` directory to storage you control. The default is `~/RoachNet/storage`; custom installs may use a different path. The backup should include Vault content, models, settings, RoachTail state, logs, and RoachClaw state. Raw secret values may live outside scrubbed exports, so preserve the configured secret store separately if you need a complete recovery.

The installer is expected to preserve existing user storage, but the v1.0.5-to-v1.0.6 overwrite path and failed-upgrade recovery have not been tested on the final artifact. Do not use irreplaceable data for RC testing.

### Rollback

Preserve the v1.0.5 DMG and its verified checksum before testing 1.0.6. If rollback is needed, quit RoachNet, preserve the 1.0.6 storage tree, reinstall v1.0.5, and restore only from a backup known to be compatible with v1.0.5. This candidate adds local state schemas, and downgrade compatibility has not been proved. Do not point v1.0.5 at a modified 1.0.6 storage tree without a tested recovery record.

### Removal

No one-click uninstaller is claimed. To remove the app while preserving data, quit RoachNet and remove only the installed app/runtime material from the chosen contained root; retain the `storage` directory. For full removal, back up anything needed and then remove the entire chosen RoachNet root. Exact removal and owned-process cleanup steps must pass Gate E before stable release.

## Local and offline boundaries

RoachNet's primary shell, Vault state, local API, RoachClaw native state, and local model endpoints are designed to stay on the Mac. The final offline-first-launch and failure behavior have not yet been tested on the 1.0.6 artifact.

Network access occurs when the user invokes or enables a network-backed lane, including:

- GitHub Releases for update checks and release downloads;
- `apps.roachnet.org` for catalog and optional pack descriptors/downloads;
- Ollama or OpenClaw-compatible endpoints when configured outside the default loopback addresses;
- OpenAI, Anthropic, OpenRouter, external memory providers, webhooks, or other remote integrations explicitly configured by the user;
- map, archive, public catalog, account/support, and media/CDN sources selected by the user;
- optional model and runtime downloads from their recorded upstream sources.

Core local surfaces must fail clearly when these services are unavailable. That behavior remains a release gate, not an assumption.

## Artifact identity and verification

No final 1.0.6 DMG exists yet. Consequently there is no honest DMG URL, byte size, SHA-256, Developer ID identity, notarization submission, or stapling result to publish here.

The Apple-host worker must generate those values from the exact staged bytes, update every surface listed in `1.0.6-publication-matrix.md`, and prove that the downloaded DMG, attached sidecar, GitHub release body, Homebrew cask, website/API/update metadata, and any included companion feed agree. A stable release body must include the final byte size and full 64-character SHA-256; this RC draft must not be promoted unchanged.
