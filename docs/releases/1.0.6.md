# RoachNet 1.0.6

Release date: 2026-10-10
Version/build: 1.0.6 / 106
Platform: Apple Silicon Mac, macOS 14 or later
Installer: `RoachNet-Setup-macOS.dmg` (ad-hoc signed, not Apple-notarized — see "Opening the installer" below)
Companion: RoachNet-iOS 0.2.0 (separate release)

RoachNet 1.0.6 replaces the bundled Node runtime with a native Swift helper, rebuilds the installer on it, and adds the native RoachTail control plane the iOS 0.2.0 companion pairs with. It was gated by hand on an M2 Pro running macOS 26.6.1 (`docs/release-gates/1.0.6-mac-gate-results.md`) and reviewed for security before publication (`docs/release-gates/1.0.6-security-review.md`).

## What changed

- **No more bundled Node.** The local runtime is `roachnet-runtime`, a native Swift helper inside `RoachNet.app/Contents/Helpers/` built only on Apple system frameworks. It serves the same loopback API as before and runs the iOS companion bridge in-process. The default build refuses to package Node.
- **Native installer.** RoachNet Setup checks for Apple Silicon and macOS 14 or later, free disk space and a writable location, stages the install beside the target, boots the staged runtime as a smoke test, and only then swaps it in. Storage is carried across upgrades; a failed install rolls back and leaves no staging folders. `roachnet-runtime --install` does the same headlessly, which is what the Homebrew cask uses.
- **RoachTail control plane.** Expiring, single-use join codes, per-device peer tokens stored as hashes, approved routes and relay metadata. The `RoachNet` hostname alias is written natively, with a one-time administrator prompt only when `/etc/hosts` needs it.
- **RoachClaw native surface.** Playbooks, service health, scoped tools, jobs, reports, memory, backups, provider routes and agent-run summaries are exposed to the Mac app; status refreshes share short-lived Ollama probes.
- **Phone lanes restored.** Chat, services, account and RoachSync over the companion bridge work with the native runtime again (they had regressed in the rewrite).
- **Bundled Ollama 0.40.2**, checksum-verified, up from 0.33.1. Models pulled with older versions are upgraded in the background on first run and the originals are kept as a backup.
- Reduce Motion stops every decorative timeline in the macOS shell; the launch guide no longer carries a stale v1.0.5 label.
- The legacy `admin/` WebUI is gone from the public tree (it remains at tag `v1.0.5`).

## Security and privacy

Fixed before publication; the full finding list is in `docs/release-gates/1.0.6-security-review.md`.

- The in-app update lane requires the release's `.sha256` sidecar, verifies the downloaded installer against it and deletes a mismatch. Previously any installer URL from the releases feed was downloaded unverified and opened.
- Malformed HTTP body framing (negative Content-Length, oversized chunk headers) no longer crashes the runtime.
- The loopback API and setup service reject non-loopback `Host` headers and non-JSON bodies, closing DNS-rebinding and browser CSRF paths.
- RoachTail join codes pair exactly once and retire after five wrong guesses; pairing devices cannot choose their own peer id.
- A paired phone can only queue downloads from public hosts.
- Secret-bearing state files are written owner-only; the companion token no longer reaches the Ollama child process; the privileged hosts-file alias accepts only a plain hostname.
- The bundled Ollama 0.40.2 carries open Go advisories with no fixed version (crafted-model and crafted-request denial of service, missing auth on model management). It binds to `127.0.0.1` and is reachable only from the same Mac; 1.1 retires the bundled Ollama.
- Dependency audit: 0 npm vulnerabilities; nothing from `node_modules` ships in the DMG. There is no telemetry.

## Install, upgrade, backup, rollback, and removal

### Opening the installer

This build is **not Apple-notarized**. On first launch macOS says RoachNet Setup cannot be verified. Open System Settings › Privacy & Security and choose **Open Anyway** for RoachNet Setup; it does not ask again. The installer clears quarantine on the app it installs. A Developer ID-signed, notarized build is the first release-engineering item on the 1.1 train.

Verify the download against the attached `RoachNet-Setup-macOS.dmg.sha256` before opening it:

```sh
shasum -a 256 -c RoachNet-Setup-macOS.dmg.sha256
```

### Fresh install

1. Quit the currently installed RoachNet version before opening the installer.
2. Open `RoachNet Setup.app` from the DMG. The default contained root is `~/RoachNet`, with the app at `~/RoachNet/app/RoachNet.app` and user data under `~/RoachNet/storage`.
3. Homebrew: `brew install --cask roachwares/roachnet/roachnet` installs the same DMG headlessly.

### Upgrade and backup

Quit RoachNet and run Setup over the existing install; `storage` is preserved. Back up existing user storage before an overwrite upgrade and keep the backup until the upgraded installation is verified.

### Rollback

Keep the v1.0.5 DMG and its verified checksum. RoachNet 1.0.6 adds local state schemas, so do not assume downgrade compatibility: restore storage from a backup made before upgrading rather than pointing 1.0.5 at a 1.0.6 tree.

### Removal

No one-click uninstaller is claimed. Quit all RoachNet-owned processes, then remove the app and runtime material under the contained root; keep the `storage` directory to keep your data, or remove the whole root for a full removal.

## Local and offline boundaries

The shell, Vault, local API, RoachClaw state and local model lanes stay on the Mac. Network access happens only when you use a network-backed lane:

- GitHub Releases for update checks and release downloads;
- `apps.roachnet.org` for the catalog and optional pack descriptors;
- Ollama or OpenClaw-compatible endpoints you configure outside the default loopback addresses;
- OpenAI, Anthropic, OpenRouter, external memory providers, webhooks or other integrations you explicitly configure;
- map, archive, public catalog, account/support and media sources you select.

Core local surfaces fail clearly when those services are unavailable.

## Artifact identity and verification

The published GitHub release lists the DMG's byte size and SHA-256 and attaches the `.sha256` sidecar. The Homebrew cask, the website and the in-app update lane all refer to the same published bytes; the update lane refuses an installer whose digest does not match the sidecar.

## Known limitations

| Limitation | Impact | Affected users | Workaround | Blocks stable? |
| --- | --- | --- | --- | --- |
| 1.0.6 ships ad-hoc signed with no Developer ID signature or notarization. | Gatekeeper blocks the first launch of RoachNet Setup. | Everyone installing from the DMG. | After the first blocked launch, open System Settings › Privacy & Security and choose **Open Anyway** for RoachNet Setup. The installer clears quarantine on the app it installs. | No. |
| The bundled Ollama 0.40.2 has open upstream advisories with no fixed version. | Local-only denial of service or model management by another process on the same Mac. | Everyone using the bundled local-model runtime. | Ollama is bound to loopback; 1.1 replaces it with the native RoachInference engine. | No. |
| Network-backed catalogs, maps, archives, updates, model downloads and remote providers do not work offline. | Those optional lanes cannot refresh or download without a connection. | Users invoking those features offline. | Pre-download owned content and local models; use local Vault and loopback model lanes. | No. |
| Windows and Linux desktop installers are not shipped. | The 1.0.6 desktop app cannot be installed on those platforms. | Windows and Linux desktop users. | Use a supported Apple Silicon Mac or the development lanes documented for contributors. | No. |
| RoachNet-iOS 0.2.0 is a separate release. | Desktop 1.0.6 does not install a new companion IPA. | RoachNetiOS users. | Install 0.2.0 from its own GitHub release or the SideStore source. | No. |
| No one-click uninstaller is claimed. | Removal means separating app/runtime files from user storage by hand. | Users removing or rolling back RoachNet. | Follow the removal steps above. | No. |
